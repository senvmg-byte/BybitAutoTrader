# Bybit Auto Trader

Standalone Flutter/Dart Android app. Market data, signed Bybit V5 requests, strategy evaluation, and bot execution run directly on the phone. A native Android foreground service keeps the trading loop active when the app is in the background; no PC or Node.js backend is required. API credentials are stored using Android secure storage.

The on-device Dart adapter maps the CCXT-style functions this app needs to Bybit V5: `loadMarkets`/`fetchMarkets`, normalized market and ticker data, `fetchOHLCV`, `fetchBalance`, open orders and positions, market/limit `createOrder`, `fetchOrder`, `cancelOrder`, leverage, and trading stops. It returns CCXT-like normalized fields while retaining Bybit market IDs and raw `info` for exchange-specific features. This is a scoped Dart implementation, not the full CCXT package; the Node.js package cannot run inside a Flutter Android APK. The existing `backend/` directory is a separate prototype and is not used by the Android app.

Supported categories: Spot, Linear, Inverse, and Options. Spot and Options are long-only; Linear and Inverse allow Long-only, Short-only, or automatic Long + Short. Derivatives request isolated margin and 1x leverage. Choose short-wave mode (closed 5-minute candles, EMA 9/21) or long-wave mode (closed 4-hour candles, EMA 20/50); both use RSI/ATR confirmation and evaluate once per minute. The Vietnamese dashboard prioritizes bot state, a live market-price and trade-scenario card, account overview, and active position; detailed settings, per-asset balances, and trade history are expandable to keep the first view concise. Demo/Live/Stop actions remain in a fixed bottom bar. The dashboard subscribes directly to Bybit's public WebSocket ticker for the selected market, independent of the chart's scroll position, and coalesces incoming prices to at most one dashboard update per 50 ms. Estimated entry, quantity, stop/target levels, and supported open-position PnL follow the latest price; strategy signals remain based on the most recently closed candle to avoid intrabar false signals. Demo mode sends real orders to Bybit's demo-trading REST host with separate Demo API credentials; Live uses separate production credentials. Public market data continues to use the production market-data host. The app shows Unified Account balances by coin (free, used, total), and recent bot order details (side, type, fill, fees, status and time). The market selector provides a searchable manual list plus a scanner for every category: it analyzes the 30 highest-turnover eligible markets using 24-hour turnover, price change, and the selected strategy's EMA/RSI; Inverse instruments are selected by USD quote (their settlement coin is the underlying, not USD), Options use the underlying Spot candles, and Long/Short selection adjusts ranking without hiding opposite-trend markets. Per-market candle failures are skipped and reported while valid results remain visible. Scanner rankings are informational and never place orders. The chart uses recent Bybit V5 candles and subscribes to public WebSocket kline and ticker topics. Both ticker last-price changes and active-kline close changes feed the live price trace and active candle; the chart retains up to 90 candles and 60 live-price samples, coalesces chart repaints to at most four per second, and repaints the canvases without rebuilding the full chart widget tree for each price event. Dashboard status polling runs every 30 seconds and rebuilds only when status data changes. Subscription errors are shown in the chart; the chart is isolated in repaint boundaries, and its stream is paused while the app is in the background.

Bybit does not provide option OHLCV in this API, so option signals and chart candles use the selected option's underlying Spot market. Orders and premium limits use the selected option quote. Options have no attached exchange stop; the phone must remain powered, connected, and allowed to run the foreground service for bot-managed exits. There is no automatic expiry/strike selection.

Spot and Linear positions use staged risk management: the bot closes 50% of the original filled size at +1R and 25% at +2R, where 1R is the entry-to-initial-stop distance. After the first partial close, the stop moves to at least breakeven and then trails the favorable price by 1.5 ATR; it is only tightened, never loosened. Linear stop changes are sent to Bybit's position trading-stop endpoint, and Spot stop orders are replaced on Bybit after a partial close or trail update. Partial take profits are checked by the foreground bot loop (about once per minute), not resting exchange-side target orders. Keep the service running for partial take-profit execution and trailing updates; the last successfully installed exchange stop remains the safety net if the app disconnects. Inverse and Options retain their existing full-exit behavior and are not covered by staged take profit/trailing stop.

## Requirements

- Flutter SDK 3.29 or newer (Dart 3.7 or newer)
- Android SDK / Android Studio for building the APK

## Run the Android app

From the project root:

```powershell
flutter pub get
flutter run
```

Open Settings and enter a separate Bybit Demo API key/secret for Demo mode and production API key/secret for Live mode. Demo mode requires a key created for Bybit Demo trading; production credentials are never sent to the Demo host, and Demo credentials are never sent to the production private-trading host. Use keys without withdrawal permission and enable only the necessary read/trade permissions. A Bybit IP allowlist may conflict with a phone's changing mobile/Wi-Fi IP; do not remove security controls without understanding the risk.

Choose a product category, wave strategy, and (for Linear/Inverse) trading direction. Select the Bybit symbol using the search button. The bot shows an ongoing Android notification while the foreground service runs. Android or device vendors may still stop background work; the app does not automatically restart the trading service after process termination or reboot. Do not force-stop the app or revoke its notification/background permissions. “Chạy Demo” submits orders to Bybit Demo; it is not an internal simulator and requires Demo API credentials and demo-account funds. Pressing Stop in Demo or Live first stops the bot, then requires typing `THANH LY` to cancel open orders account-wide, close Linear/Inverse/Options positions, and market-sell available Spot balances that have a tradable USDT/USDC pair in that same environment. USDT is retained; unsupported assets, dust, and failed orders are listed and are not reported as liquidated. This affects manual orders and positions too. Android stopping the foreground service outside the app does not trigger liquidation.

Test strategies in Demo first. Demo and Live order execution and account-wide liquidation have not been validated with real funds; verify API permissions and confirm every order, balance, and position directly on Bybit after a liquidation attempt. Demo trading uses simulated exchange funds, but sends actual orders to the Bybit Demo environment. The app cannot guarantee fills, market availability, or cancellation during exchange/network failures. Options have no exchange-side stop-loss and depend on the phone service remaining connected.
